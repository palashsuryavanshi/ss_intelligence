# Data Lifecycle

## Screenshot Lifecycle

```
MediaStore discovery
  → PENDING (index queue)
    → PROCESSING (OCR, extraction, visual analysis)
      → COMPLETED (indexed, searchable, assistant-usable)
        → Derived data generated:
          • OCR blocks
          • Extracted URLs, dates, phones, prices, OTPs, receipts
          • Semantic embeddings
          • Visual analysis (dhash, colors)
          • Knowledge graph entities/relations
          • Topics, sessions, events, tags (autonomous analysis)
          • Contextual actions
        → User deletion cascades to all derived data
        → Full rebuild requeues all as PENDING and regenerates
      → FAILED (error recorded, re-queuable)
```

## Derived Data Lifecycle

All derived data is **regenerable** from the screenshot index. Clearing any
derived table never touches the original screenshot index.

| Derived Data | Regenerated By | Cleared By |
|-------------|----------------|------------|
| OCR blocks | ScreenshotProcessor | Clear Index |
| Extracted entities | MetadataExtractor | Clear Index |
| Semantic embeddings | SemanticIndexWorker | Clear Data |
| Visual analysis | VisualIndexWorker | Clear Data |
| Topics/sessions/events | AutonomousAnalysisWorker | Clear Data |
| Knowledge graph | GraphRepository | Clear Data |
| Assistant history | Persistent (configurable) | Clear History |
| Search history | Persistent (configurable) | Clear History |
| Automation rules | User-created (manual) | Clear Rules |
| Expense records | User-confirmed | Delete per record |

## User-Configurable Lifecycle

From Settings > Privacy:

- **Search History**: Default OFF. When OFF, queries are not persisted.
- **Assistant History**: Default ON. When OFF, conversations are not persisted.
- **Analytics**: Default OFF. When OFF, no behavioral tracking.
- **Crash Reporting**: Default OFF. When OFF, no crash data collected.

## Complete Deletion

Settings > Privacy > Delete All Data:

1. Counts screenshots for confirmation
2. Clears action history, reminders, expenses, automation rules
3. Clears autonomous analysis (topics, sessions, events, tags, suggestions)
4. Clears all screenshots (cascades to OCR, entities, visuals, graph, etc.)
5. Clears search history
6. Clears semantic embeddings and categories
7. Clears visual features
8. Clears knowledge graph
9. Clears assistant conversations, messages, evidence, snapshots
10. Reports count of deleted screenshots

## Per-Screenshot Deletion

When a screenshot row is deleted, SQLite `ON DELETE CASCADE` automatically
removes:

- Extracted URLs, dates, phones, prices, OTPs, receipts
- OCR blocks
- Semantic embeddings, visual analysis
- Knowledge graph relations
- Collection memberships
- Automation executions referencing that screenshot
- Action history, reminders, expense records

No orphaned data remains.
